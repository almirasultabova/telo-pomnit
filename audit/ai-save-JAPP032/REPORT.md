## Подтверждено

1. Второй снимок: «Проверить экраны → Мой путь · без записей». Фикстура запрещает localStorage и любой POST /checkins, поэтому штатный интерфейс показывает memory-only и «Повторить отправку». Это дефект учебного сценария, не доказательство потери серверных данных. Исправление: пять оценок/заметка сохраняются в памяти изолированной фикстуры, редактирование того же московского дня не создаёт дубликат; история видит пример. При переоткрытии просмотра пример сбрасывается, настоящие API/данные не затрагиваются. Статус явно говорит «Учебный пример сохранён только в этом просмотре. Ваши настоящие данные не изменены». Main не содержит включения ScreenReviewMode.

2. AI: по обезличенным nginx/приложенческим журналам реальные POST /ai/chat 15 октября около 15:47–15:48 МСК получили 503; провайдер вернул 429. Для уточнения выполнены два технических запроса с существующего сервера: пустой JSON дал 400, JSON только с model=gpt-4o-mini, без messages — **429, error.type=insufficient_quota**. Оба не содержали сообщений, не могли создать completion; ключи/личные тексты не выводились. Недостаточная квота означает доступные кредиты/лимит расходов API, точный баланс не читался. Никакого пополнения, смены ключа/модели/провайдера не выполнялось. Ответы живого AI не восстановлены.

3. Кнопка AI работает с заглушкой. На период запроса отсутствовал понятный статус, а после ошибки выбор контекста оставался disabled: рендер происходил пока aiPending=true. Локально добавлены видимый статус ожидания и ошибка рядом с полем; после завершения перерисовываются элементы контекста, текст не очищается при отказе, кнопка вновь доступна. Черновики остаются изолированными по владельцу/разговору; переход к другому разговору сбрасывает только сообщение ошибки. Backend различает недостаточную квоту, обычный 429 и иной отказ без журналирования текстов/ключей.
