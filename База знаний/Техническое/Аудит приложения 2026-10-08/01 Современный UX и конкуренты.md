## Что считать качеством приложения в 2026 году

Для «Тело помнит» современность определяется тем, что участница может быстро и спокойно записать своё состояние, найти встречу и доверять сохранению личной записи. Сама по себе новая графика, AI или стек этого не обеспечивают.

| Критерий | Проверяемый результат для нашего приложения |
|---|---|
| Ясное действие | На главном экране одно основное действие: новая запись; история и дополнительные инструменты не конкурируют с ним одинаковой важностью |
| Короткий путь | Состояние можно отметить без обязательного свободного текста; расширить запись можно отдельно |
| Честное сохранение | Различаются «на устройстве», «отправляется», «на сервере», «не удалось»; ошибка не выдаётся за окончательное сохранение |
| Доступность | Управление одной рукой, увеличенный текст, клавиатура и screen reader; выбранное состояние объявляется не только цветом |
| Спокойное движение | Переход объясняет смену экрана; декоративное движение выключается по системному reduced motion |
| Разные состояния доступа | Ожидание заявки, отказ, одобрение без покупки, активная программа и архив имеют самостоятельные объяснения и действия |
| Надёжное восстановление | Повторный вход возвращает правильные данные и права; прерванная запись остаётся черновиком |
| Подходящая визуальная среда | Крем, зелёный, природные детали и телесная карта связаны одним языком; интерфейс не превращается в тяжёлый кинематографический лендинг |

Основа системы: [Material 3 Foundations](https://m3.material.io/foundations/) связывает доступность, tokens и состояния компонентов. Конкретную страницу Material 3 Structure веб-инструмент прочитал только как JS-заглушку; численные правила касания ниже подтверждены доступным официальным Google источником, а не этой заглушкой.

Apple рекомендует заметное основное действие и область кнопки порядка 44×44 pt; Google — цель касания 48×48 dp с достаточным расстоянием. Это платформенные единицы, их нельзя буквально объявлять нормативом CSS. Для Mini App предлагается собственный инженерный стандарт 44–48 CSS px для основных действий с проверкой на телефоне. [Apple HIG Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons?changes=la_11), [Google Touch target size](https://support.google.com/accessibility/android/answer/7101858?hl=en).

WCAG 2.2 AA задаёт минимальную цель 24×24 CSS px с исключениями и альтернативой достаточного расстояния; это нижняя граница, не оптимальный размер ежедневного touch-интерфейса. Размер видимого значка не равен области касания. [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html).

## Подтверждённые проблемы исходников

### UX-01. Невидимые экраны не исключены из доступной навигации

`.screen` в CSS скрывается через opacity:0 и pointer-events:none; `goTo()` переключает только классы. В роутере нет `inert`, `aria-hidden`, удаления tab-stop или переноса фокуса. Следовательно, модель скрытия не закрывает экран для клавиатуры и вспомогательных технологий. Доступность тела особенно проблемна: SVG paths имеют data-zone, но не доступное имя, роль или клавиатурное действие; обработчик `.zone-btn` существует, но их создание в текущем рендере карты не найдено.

Рекомендация P0/S–M: скрывать неактивный экран от взаимодействия и дерева доступности; переносить фокус на заголовок нового экрана, возвращать на вызвавшую кнопку при закрытии; добавить альтернативный список зон, полноценные checkbox/aria-pressed для ощущений, активное состояние вкладок. Критерий: весь дневник заполняется без касания SVG и без попадания Tab на невидимые кнопки. Полное соответствие WCAG этим одним исправлением не достигается.

### UX-02. Масштабирование запрещено, мелкий текст широко используется

`app/index.html:6` содержит maximum-scale=1.0,user-scalable=no. Подписи навигации — 10px, метаданные и некоторые содержательные подписи — 11–13px. Мелкий текст сам по себе не является доказанным нарушением, но масштабирование и реальная читаемость требуют исправления/проверки. Многие подписи дополнительно ослаблены opacity.

P0/S–M: разрешить масштабирование, обеспечить reflow/доступ к кнопкам при увеличении текста до 200%, составить типографическую шкалу. Предлагаемая база: основной текст 16px, значимая подпись 14px, 12px только для второстепенных метаданных; навигация 12–13px. Это проектная рекомендация, не универсальный стандарт. [WCAG Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html).

### UX-03. Reduced motion отсутствует

В CSS/JS не найдено prefers-reduced-motion/matchMedia для движения. Есть бесконечные пульсации splash, flameDance, breathe, анимированные слайды каждого экрана и всплывание сохранения. P0/S: режим reduced motion убирает трансформации/декоративные циклы, сохраняя ясные мгновенные состояния. Для обычного режима оставить краткие переходы, убрать постоянный огонь серии дней. WCAG 2.3.3 — AAA, поэтому нельзя объявлять отсутствие reduced motion автоматическим нарушением уровня AA. Автоматические длительные анимации отдельно проверяются по 2.2.2. [WCAG Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html).

### UX-04. Сохранение визуально надёжнее, чем фактически

`Storage.saveDiaryEntry()` сначала сохраняет запись в локальный кеш, запускает серверный POST и подавляет ошибку `.catch(() => {})`. Такой же подход виден для реакций/чекинов. Локальный кеш ограничен 90 записями. При блокированном persistent storage используется память текущего окна. В сочетании со скрытой ошибкой это создаёт риск потери записи, хотя экран уже показал успех.

P0/M–L: состояние синхронизации, idempotent очередь отправки, явный повтор и восстановление черновика. Наименование успеха должно соответствовать уровню сохранения. До готовой очереди не обещать полноценный offline. Запись дневника — важнее декоративного редизайна.

### UX-05. PDF на кнопке означает HTML в реализации

`app/index.html:335` — кнопка «📄 PDF», `exportDiaryPdf()` в app.js:1568 создаёт Blob text/html и имя .html. Это подтверждённое несовпадение обещанного и результата. P0/S для честного названия «Экспорт», P1/M для настоящего PDF + CSV/JSON по выбору; отдельно проверить скачивание на iPhone Telegram. Экспорт только текущих 90 кешированных записей нельзя называть полной выгрузкой аккаунта без серверной пагинации.

### UX-06. Мобильная оболочка учитывает только часть Telegram viewport

Есть CSS env(safe-area-inset-bottom) и 100dvh, но интеграция contentSafeAreaInset/safeAreaInset/viewportStableHeight событий SDK не найдена. Чат и фиксированные нижние действия нужно проверять при клавиатуре, компактном окне Telegram и изменении высоты. P1/M: совместимый fallback для старых версий SDK и обработка актуальных inset/viewport событий. Не требуется автоматически включать fullscreen. [Telegram Mini Apps](https://core.telegram.org/bots/webapps).

### UX-07. Заявленная тема Telegram фактически принудительно светлая

`applyTgTheme()` задаёт фиксированные кремовые/зелёные цвета вместо Telegram themeParams. CSS dark-mode меняет часть рамок/теней, но не эту базу. Нет обработчика themeChanged. Это не доказательство, что приложение обязано повторять тему Telegram; это неполная модель собственного режима. P1/M: выбрать и явно реализовать «системная / светлая / тёмная» либо документировать единый брендовый светлый режим; проверить контраст всех состояний. Не считать CSS dark media полноценной тёмной темой.

### UX-08. «Мой путь» привязан к старым календарям

getStreamWeek() использует 16 апреля; отдельные интервалы Н1–Н5 — март/апрель; итог потока включает дату 15 мая; количество встреч берётся из исторического DATA.program.schedule. Поэтому новая октябрьская группа не получает достоверную аналитику по своим неделям, даже когда её расписание показывается правильно. P0/M: аналитика выбирает поток/период из серверного календаря; «все записи» отдельно от «эта программа»; графики сообщают даты, количество наблюдений и недостаток данных. Это исправление факта, не просьба добавить больше диаграмм.

## Как усилить визуально без лишней нагрузки

Предлагаемое направление — спокойный личный инструмент в природном языке «Тело помнит». Связь с сайтом можно выразить кремовой поверхностью, зелёным акцентом, небольшим рисунком ветви/корней и ясной телесной картой. Полноэкранные видео, 3D и обязательный проход через заставку для ежедневной записи не нужны. Новое направление не считать утверждённым.

1. Главный экран: компактное приветствие/дата → заметное «Сделать запись» → последняя запись и её sync → два вторичных инструмента. Серия дней перестаёт занимать первое место; её можно заменить спокойной формулировкой числа дней наблюдения без наказания за пропуск.
2. «Мой путь»: один основной итог за выбранный период, затем карта/ощущения, по нажатию подробности. У каждой визуализации подпись периода и число записей. Без псевдодиагностической окраски.
3. «Мой поток»: следующая встреча и действия Zoom/чат наверху, расписание ниже, анкета/профиль/экспорт/настройки отдельно. Ведущей заявки лучше вынести в отдельный служебный маршрут: список допусков не должен смешиваться с личными наблюдениями участницы.
4. Набор компонентов: primary/secondary/danger действия; loading/error/empty/success; spacing tokens 4/8/12/16/24; две поверхности и одно смысловое выделение. Сохранить мягкие углы; не использовать стекло/тени одинаково повсюду.
5. Иконки: небольшой единый набор вместо смешения крупных emoji и line-icons, но emoji допустимы как понятные ощущения. Декор скрыт от screen reader; подписи действий остаются текстовыми.
6. Motion: небольшое появление подтверждения, смена состояния кнопки, ясный переход назад. Без бесконечного движения, fake progress и задержки чтения; haptic оставлять для понятного результата, по желанию выключать.

## Приоритет и относительная стоимость

S — ограниченная правка одного маршрута/компонента; M — несколько компонентов с проверками; L — серверная модель/хранилище и восстановление. Это сравнительная сложность, не согласованный срок или смета.

| Очередь | Работа | Размер | Риск/зависимость | Проверка результата |
|---|---|---|---|---|
| P0 | Честное сохранение/очередь/черновик | M–L | Конфликты кеша/сервера; нужен согласованный privacy режим | Отключить сеть при записи, закрыть/открыть, восстановить и отправить без дубля |
| P0 | Исправить период «Мой путь» | M | Несколько потоков, timezone, архив | Октябрьская запись попадает в правильную неделю; весенние не смешиваются |
| P0 | Закрытые экраны/focus/list зон | S–M | Совместимость inert и модальных окон | Tab/Enter/VoiceOver проходят доступный маршрут |
| P0 | Zoom/reduced motion/честное название экспорта | S–M | Нижние действия/таблицы при крупном тексте | 200%, малый viewport, reduced motion, формат скачанного файла |
| P1 | Типографика/контраст/единые состояния/нижние касания | M | Нужны реальные скриншоты и визуальная приёмка | 320–430px, низкая высота, все состояния и touch targets |

Конкретные участницы, сроки и обязательства ведущих этим предложением не назначены.
