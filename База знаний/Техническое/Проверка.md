## Модель доступа — матрица приёмки

### Историческая запись проверок от 22 сентября 2026

Ниже сохранён отчёт предыдущей итерации. При уборке структуры эти моки и бизнес-сценарии заново не выполнялись.

- Node VM-моки: граница перехода 22.09 16:00 — 29.09 16:00 МСК, новые аккаунты, pending/cancelled, служебный admin, несколько потоков, последний день программы, 3 календарных месяца записей, совместимость исторического зачисления без paidAt.
- Fastify inject: запрещённый POST `/ai/chat` возвращает 403 до вызова модели; чтение своего диалога разрешено, чужого — 404.
- Edge headless, mocked API, 375×667 / 768×1024 / 1440×1000: открытый/закрытый AI, чтение истории и отправка, выбор своего потока, экранирование текста, отсутствие JS-ошибок и горизонтального overflow. Никаких реальных AI-запросов, оплат или Telegram-рассылок.
- HTML-вложенность/уникальность ID, `node --check`, `git diff --check`.
- Это не проверка реального права на файлы Telegram: клиент/сервер скрывают закрытые ссылки по сроку, но членство и старые приглашения управляются внешней платформой. Полная бизнес-приёмка ниже остаётся ориентиром, в том числе для ещё не согласованной численной квоты AI.

**Полная матрица приёмки; исторический объём выполненных проверок указан выше.** Источник условий — [Приложение и экосистема](../07%20Приложение%20и%20экосистема.md), технические правила — [Развёртывание](Развёртывание.md). Использовать тестовые аккаунты/моки оплаты и фиксированное серверное время, без списаний и рассылок реальным участницам.

| Сценарий | Ожидаемое поведение |
|---|---|
| Новый авторизованный аккаунт без покупки | Создаёт/читает свои diary, triggers и checkins; AI не вызывается; чужих закрытых ссылок нет |
| Оставлена заявка или оплата pending | Не появляется платный доступ |
| Будущий поток оплачен, старт ещё не наступил | Бесплатные функции работают; AI этого потока ещё закрыт |
| Оплаченный поток идёт | AI разрешён в пределах согласованного лимита; доступны свои встречи, не чужие |
| Последняя встреча / точная граница окончания | До конца согласованного периода AI работает; с границы — нет, независимо от cron и часов телефона |
| Завершённый поток | Можно добавлять записи и реакции; сохранённая история AI читается; новые сообщения AI запрещены до вызова модели |
| Окончание AI-доступа при открытом чате | Следующий запрос сервер отклоняет; введённый текст не теряется, объяснение понятное |
| В пределах 3 месяцев после финала | Записи своего оплаченного потока доступны, AI уже закрыт |
| После срока записей встреч | Закрыты записи встреч, но не личный дневник/реакции/сохранённая история AI |
| Повторная покупка, несколько зачислений | Новое расписание отдельно; единый дневник; действующее право не перекрывается старым completed или будущим потоком |
| Отмена/полный возврат | Платные права соответствующего потока отозваны; бесплатные данные не удалены |
| Подмена streamId/sessionId, прямой POST /ai/chat, старый JWT/кэш | Не дают чужих данных или обхода серверных платных прав |
| Публичный анонс следующей группы | Не содержит закрытых Zoom/chat/recording URL; не подменяет архив купленного потока |
| Сбой сети, новый вход, смена устройства | Не обходят ограничения и не приводят к потере личных записей; бесплатная часть не закрывается из-за отсутствия enrollment |

Отдельно проверить авторизацию, удаление аккаунта и экспорт: новая модель не должна отменять существующие механизмы приватности. На 375/768 px не должно быть общего экрана оплаты поверх дневника выпускницы. Диагностику и прочие не перечисленные функции не переводить в платные без решения владельца.

### Историческая миграция очереди — не повторять автоматически

SQL сохранён для объяснения происхождения колонок, а не как шаг текущего деплоя. Перед любой отдельно согласованной миграцией проверить фактическую схему и резервную копию `waitlist_entries`. Добавление колонок не включает старые записи в отправку.

```sql
BEGIN;
ALTER TABLE "waitlist_entries"
  ADD COLUMN "notification_pending" BOOLEAN NOT NULL DEFAULT false,
  ADD COLUMN "notification_retry_at" TIMESTAMP(3),
  ADD COLUMN "notification_attempts" INTEGER NOT NULL DEFAULT 0,
  ADD COLUMN "notified_admin_ids" TEXT[] NOT NULL DEFAULT ARRAY[]::TEXT[];
CREATE INDEX "waitlist_entries_notification_pending_notification_retry_at_idx"
  ON "waitlist_entries" ("notification_pending", "notification_retry_at");
COMMIT;
```

Затем обновить схему, выполнить установленный `prisma generate`, обновить JS, `node --check`, `pm2 restart telo-backend`. Проверить `/health`, закрытость `/admin/waitlist`, nginx и обе копии admin.html (лендинг и Mini App). SQL не идемпотентен: повторять только после проверки колонок, не запускать второй раз автоматически.

Метрика в концепции пока НЕ включена. События подготовлены по документации [reachGoal](https://yandex.ru/support/metrica/ru/objects/reachgoal); для активации нужны согласованный privacy/consent flow и цели `participation_view`, `application_open`, `application_success`, `application_error`, `telegram_click` в счётчике. Никакие ответы интерактива или контакты не входят в payload целей.

Проект «Тело помнит» состоит из трёх частей: **лендинг** (Beget VPS), **Telegram Mini App** (Beget VPS), **Backend API** (Beget VPS).

## Часть 1: Лендинг

### Как открыть локально

```powershell
node scripts/build-static.mjs
powershell -NoProfile -File scripts/check-structure.ps1 -Built
python -m http.server 8080 --directory output/site
```

У обычного Python HTTP-сервера нет nginx-маршрутов `/`, `/guide`, `/privacy`: открывайте соответствующие `.html`. Публикационные медиа используют `/media/...`; прямое открытие HTML через `file://` не подходит.

## Часть 4: Подготовка к публикации

Единая актуальная инструкция — [Развёртывание](Развёртывание.md). Сначала `node scripts/build-static.mjs`, затем `powershell -NoProfile -File scripts/check-structure.ps1 -Built` и браузерная приёмка. Публикуется содержимое `output/site/` или `output/app/`, включая только их публичные медиа. `media/library/`, базу знаний и корень репозитория на публичный хостинг не копировать.

Сайт и приложение публикуются вручную после согласования; `git push` не является деплоем Beget. Проверить на домене страницы, пути `/media/...`, консоль и согласованный пользовательский сценарий. Повторная проверка после структурных изменений не означает, что тексты сайта утверждены.

Бэкенд обновляется адресным переносом проверенных локальных файлов и перезапуском только `telo-backend`. При изменении окружения используется `pm2 restart telo-backend --update-env`. Историческую команду `git pull` с перезапуском всех PM2-процессов повторять не следует. SQL выше не является обязательным этапом текущей публикации.

| Симптом | Где смотреть |
|---|---|
| Белый экран в Mini App | F12 → Console → красные ошибки |
| Скрипт не загрузился | Порядок `<script>` в `app/index.html`, наличие файла в `output/app/js/` |
| Данные не сохраняются | F12 → Application → Local Storage → ключи `tp_*` |
| API возвращает 401 | JWT истёк или initData невалидна |
| Бот не отвечает | `pm2 logs telo-backend` на сервере |
| HTTPS не работает | `nginx -t && systemctl reload nginx` на сервере |
| Сайт долго грузится или `ERR_CONNECTION_RESET` | Проверить Cloudflare DNS: A корня → `45.11.93.236`, CNAME `www` → `telo-pomnit.ru`, обе DNS only |
| Edge показывает `STATUS_BREAKPOINT` на силуэте тела | Убедиться, что лендинг использует `body-glow.png`; `body-glow.webp` отключён из-за сбоя Edge |
