## 2. Целевая архитектура четырёх разделов

`screen-home` остаётся контейнером главных вкладок. Новый `tab-main` — «Главная»; существующие `tab-diary`, `tab-diag`, `tab-profile` сохраняют внутренние ID и получают целевое оформление. ID `diag` не означает возврат к старой диагностике; `profile` остаётся техническим ID нового «Профиля». Внешний router и URL экранов не вводятся.

| Раздел | Содержание и источники | Что происходит при нажатии |
|---|---|---|
| Главная | Имя подтверждённого пользователя, одна согласованная поддерживающая карточка, три действия тело/реакция/состояние, последние доступные наблюдения, контекст потока из programAccess | Запускает те же сценарии, что Дневник; переход к потоку ведёт в Профиль; к аналитике — в Мой путь |
| Дневник | Центр трёх инструментов и три существующие истории; статус дневниковой очереди и ошибки загрузки | Тело → карта → ощущения → необязательная заметка → сохранение; реакции → действующая форма; состояние → пять шкал |
| Мой путь | Свой выбранный поток/период, опрос v2, график пяти шкал, карта, частоты ощущений, заметки, статистика | Существующие selector/недели/опрос/ответы; нет нового автоматического толкования показателей |
| Профиль | Собственный профиль, вложенный блок Мой поток, расписание/права/ведущие, анкета, feedback, данные/приватность; служебные заявки только администратору | Существующие API и действия; вход в свои AI-диалоги доступен также при отсутствии права писать |

Нижняя навигация показывается в четырёх главных разделах. Формы и приватные действия сохраняют последовательный маршрут с BackButton; постоянную нижнюю навигацию внутри каждой формы из картинок автоматически не переносить. Точный охват навигации вложенных экранов — пункт визуальной приёмки.

### Состояния Главной

1. Допущенная новая участница без записей и потока: три инструмента, реальные пустые состояния, без фиктивного прогресса.
2. Свой предстоящий оплаченный поток: даты и ближайшая встреча по API; права attend/AI ещё могут быть закрыты.
3. Активный поток: его контекст и доступные действия по canAttend/canReadRecordings/ai.canWrite.
4. Между потоками / завершённый поток: личные инструменты и допустимый архив; истёкшие ссылки не показываются.
5. Служебная роль: не выдавать ведущую за оплатившую участницу; сохранять служебные права и отсутствие анкеты участницы.
6. Ошибка получения прав или истории: объяснение и повтор, без вывода «нет потока/нет записей» на основании сбоя.

Pending/rejected/revoked/401 остаются системным экраном перед Главной, с отдельным входом в права на собственные данные. Обход допуска через новую вкладку невозможен.

## 5. Дизайн-система и компоненты

Первоначальные семантические роли из текстового ТЗ: `--color-bg:#F7F4EF`, `--color-surface-warm:#E9E1D6`, `--color-action:#2A4A38`, `--color-sage:#DDE4D8`, `--color-text:#1A211A`, `--color-text-muted:#726A60`. Это набор для проверки, не разрешение молча разрешить расхождение с листом17. Error/warning/success/border/focus и пять цветов графика выбирать отдельно с измерением контраста. Шалфей не является автоматически цветом мелкого текста.

Группы CSS variables:

- Цвета: background/surface/surface-warm/action/action-hover/text/text-muted/border/focus/success/warning/danger/on-action; chart-tension/anxiety/energy/safety/body-contact.
- Геометрия: space-8/12/16/20/24/32, page-gutter, radius-field/card/sheet/button, control-min-height, touch-min-size, nav-height, safe-top/bottom, content-max-width.
- Типографика: font-body/font-display, text-caption/body/card/title, line-height-body/title, weights. Кириллица и fallback обязательны. Конкретная пара шрифтов требует решения из-за расхождения PDF.
- Движение: motion-fast/normal 150–250 мс, easing, shadow-subtle; reduced motion отключает непрерывные и крупные переходы. Согласовать JS timeout удаления классов с реальной длительностью CSS.

Старые `--tg-*`, `--accent`, `--card-*`, `--radius-*`, `--font-*` сохранить через совместимые роли. `applyTgTheme` не должен перекрывать новые значения прежними hardcoded цветами. Dark media query сейчас меняет лишь часть переменных поверх фиксированной светлой темы: нельзя считать это готовой тёмной темой.

Компоненты остаются HTML/CSS/небольшими render-паттернами, без React/UI-kit:

1. Заголовок экрана, подзаголовок, компактный eyebrow, section header с вторичным действием.
2. Primary/secondary/text/destructive кнопки: normal/pressed/focus/disabled/loading; основные 52–56px, касание минимум44px.
3. Input/textarea/select с label/help/error, 16px и высотой минимум48px; focus виден, текст можно выделять в приватных записях.
4. Карточки: поддержка, действие инструмента, запись, поток/встреча, профиль, результат опроса; один основной CTA на смысловую зону.
5. Chips/checklist/segmented control/range c доступным pressed/selected и клавиатурой; seven quiz choices не превращаются в безымянные цифры.
6. State panel loading/empty/error/retry, sync badge с server/local/memory-only, inline notice/toast.
7. Четыре nav items с едиными inline SVG; адаптивные подписи, отдельный badge администратору.
8. Native details/sheet/modal с фокусом, закрытием и возвратом; privacy/delete/context остаются явными подтверждениями.
9. График с легендой и текстовыми значениями, карта с текстовым списком зон.

Не применять общую увеличенную display-типографику ко всем подписям; большой editorial заголовок предназначен для главных разделов. Природные фотографии дозируются на Главной/вступлении/empty; поля, графики и согласия читаются на устойчивой поверхности. В рамку телефона/статусбар/iOS chrome из PDF приложение не оборачивается.

Настоящие миграции не являются тестом frontend редизайна.

Обязательные assertions новой навигации: четыре кнопки и одна active; правильный tab/экран после каждого click; одинаковый owner до/после; отсутствие POST от nav; back из формы возвращает к источнику; quiz back не выпадает в старый screen-question; closeDataRights не возвращает к чужому owner; repeated activation не дублирует handler; после403 никакая nav не открывает private DOM. Не ослаблять эти assertions ради зелёного результата.

## 11. Противоречия и вопросы для решения владельца

Перечень зафиксирован без самостоятельного выбора спорной версии. Новое прямое сообщение подтверждает саму концепцию редизайна и четыре раздела; старый статус «концепция/число вкладок не утверждены» становится историческим. Остальные разногласия не считаются автоматически отменёнными.

1. **Шрифты:** текст PDF стр3 — Cormorant Garamond/Manrope; лист17 — Playfair Display/Inter. Требуется выбрать рабочую пару. Временный fallback при испытании возможен, но не считается утверждением другой пары.
2. **Палитра:** стр3 даёт шесть конкретных токенов; лист17 показывает другие оттенки, в том числе более оливковую базу/текст. Требуется определить, что является рабочей палитрой. Контраст проверяется после выбора; фото не измеряются как flat HEX.
3. **Порядок этапов:** PDF разделяет tokens1 и shell2, прямой запрос требует tokens+новую навигацию первым этапом. План отражает прямой запрос как этап1А/1Б; это явно названная адаптация очередности, не скрытая правка ТЗ.
4. **Вкладки на визуальных листах:** листы8/11 местами показывают три вкладки/Мой поток; целевой текст и прямой запрос требуют четыре. В картинках остаётся историческая композиция; окончательная её адаптация нуждается в визуальной оценке.
5. **Шкалы:** макеты используют «Спокойствие» и иную композицию; код/text specification — tension/anxiety/energy/safety/bodyContact с диапазоном1–10. Не менять ключи/смысл под картинку. Лист12 выглядит как ось1–5/даты, код — недельные средние1–10. Нужно согласовать точную визуальную адаптацию графика.
6. **Опрос:** лист13 содержит1–7 и результаты «Стремление к контролю/Повышенная чувствительность»; текущий Habitual v2 имеет частоты0–4 плюс два неопределённых ответа и четыре другие группы. Нужна адаптация макета, не замена методики. История всех результатов/динамика/поделиться не являются существующим UI.
7. **Реакции:** лист10 предлагает свободный ответ «как отреагировала»; текущая форма требует enum reactionType и ситуацию. Свободный текст не заменяет обязательный выбор. «Сохранено/синхронизировано» на картинке не подтверждено механизмом реакции.
8. **Единая история/PDF:** картинки объединяют три типа и показывают поиск/календарь; текущие histories раздельные, PDF серверный дневник тела. Выбор объединённого списка/PDF всех типов — отдельное функциональное решение.
9. **J-248 против ограничений PDF:** свободная запись, поиск/важное, исходный запрос/итог и private вопросы ранее приняты для проработки; PDF не включает их как готовые функции. Не отменять J-248 и не включать автоматически в редизайн. Требуется решить, какие добавить отдельной очередью после визуального переноса.
10. **J-247 и визуалы материалов:** листы8/14 показывают практики/материалы; библиотека снята владельцем, материалы в Telegram. Внешние доступные ссылки по API допустимы; встроенный плеер/LMS не создавать.
11. **Приватность:** лист16 обещает «только тебе»/обезличенное AI и удаление всего через checkbox; код передаёт выбранные данные OpenAI, авторизует отдельные служебные маршруты и сохраняет предусмотренные финансовые сведения/tombstone, требует typed phrase. Буквальный текст/механика из картинки конфликтуют с действующими правилами. Нужна согласованная редакция; T-010 не закрыта.
12. **Offline/допуск:** лист16 показывает «ответ обычно24часа»/«продолжить офлайн», лист15 обещает автоматическую отправку после восстановления сети. Нет общего подтверждённого механизма/срока; не переносить обещания. Проверенный JWT/допуск обязателен, queue/AI drafts не равны общему offline mode.
13. **AI тон и роль:** макет обращается на «ты», изображает широкую интерпретацию/online; действующий UI J-242 и server prompt на «вы», с обозначением OpenAI/границ. Редизайн не разрешает менять prompt/роль/обращение; новая содержательная редакция отдельно.
14. **Данные потока:** фото/имена участницы/ведущей, номер встречи, даты и progress из картинок не соответствуют контракту. attendance функция есть в остатках, но current schedule не предоставляет подтверждённую отметку присутствия. Процент посещения/прохождения из макета не вводить.
15. **Документация отстаёт:** app/CLAUDE.md старая схема не включает boot/habitual и описывает legacy quiz/keys; свежие J-238–J-242 и code содержат исправления. Обновить карту после внедрения, исторические записи не переписывать.
16. **Ссылка следующего набора:** renderSchedule ссылается на landing_concept.html, сборщик публикует landing_final.html. Static mismatch подтверждён, live404 сейчас не проверялся. Исправление URL/публичного назначения — отдельное явно согласованное действие, не автоматический перенос из картинки.

## 12. Что не превращается автоматически в функции

Голосовые заметки/микрофон, встроенное видео/аудио, LMS/практики, checkout, избранное/поиск, AI session titles/search, notifications/settings/edit profile, календарь всех записей, динамика истории опросов/share, автоматические «инсайты»/проценты изменения/посещаемость и новые советы. Декоративный bell/gear/heart/calendar не получает действие без реального сценария. Иллюстрации тела не заменяют геометрию35 текущих selectable зон без проверки. Размытая AI-картинка/условная надпись не является исходником фото/готовым UI-текстом.

## 13. Результат для подтверждения

Предлагаемый первый разрешаемый объём: baseline → совместимые semantic tokens/базовые компоненты → shell с четырьмя вкладками и минимальным новым входом → локальная регрессия/предпросмотр.
