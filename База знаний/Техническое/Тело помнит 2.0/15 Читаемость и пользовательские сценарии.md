## Подтверждённые замечания и направление

Главная: поднять поддерживающую реплику к плечу и основной текст; сохранить зелёный, придать главному действию опаловую глубину вместо плоской заливки. Статичная героиня — иллюстрация, не персональный аватар; автоматическая смена фотографий не добавляется. Оливки в карточках потока и поддерживающих блоках отвергнуты.

Дневник: отделить сегодняшнюю запись, действия и историю; последние записи свернуть, ограничить краткий список и оставить полную историю. Формы реакции и состояния, история и аналитика: увеличить различимость поверхностей, выделить активный выбор, использовать Manrope в рабочих подписях и антикву в заголовках.

AI: компактное начало разговора, ясное поле сообщения, видимая отправка при многострочном тексте/клавиатуре. Передачу сообщений OpenAI и выбор дневникового контекста объяснять коротко; подробности раскрываются отдельно, явное подтверждение выбранных записей сохраняется.

Приватность: исключить техническую инфраструктуру из основного текста; скачивание дневника первично, полная/локальная копии данных и восстановление доступа — дополнительные действия. Проверка владельца остаётся автоматической. Предпросмотр JSON в приложении с рабочим возвратом вместо открытия внешнего просмотрщика.

Встречи: вернуть заметное раскрытие темы/подготовки и существующую локальную отметку участия, строго по реальным meeting ID. Zoom — только при canAttend и реальной ссылке. Не подставлять старое расписание/фиктивные ссылки. Telegram обеих ведущих восстановлен по действующим источникам проекта; происхождение контакта Анастасии указано ниже.

Потоки: API возвращает только собственные оплаченные enrollment и служебные разрешения; выбор не ограничивается первым входом. По умолчанию действующий, иначе предстоящий, иначе доступный архив. Дневник сохраняется целиком, «Мой путь» фильтруется по датам выбранного потока. Анкета скрывается для служебной роли/после заполнения; показать её состояние, не разрешать повторную запись молча. Схему хранения анкеты и право доступа не менять.

### Незавершённый вопрос анкеты

Служебная роль не получает анкету участницы; для заполненной анкеты показано явное состояние. В старом коде обнаружен общий локальный флаг заполнения и привязка проверки к потоку при старте, без обновления после выбора другого потока. Поэтому наличие анкеты для следующего потока нельзя считать проверенным. Эта логика в текущем проходе не переписана. Следующий отдельный шаг T-030: согласовать отображение статуса выбранного потока с существующим API анкеты, проверить смену потока и владельца без изменения методики или схемы хранения. Backend для чтения статуса по stream ID уже существует; необходимость серверных изменений этим наблюдением не установлена.
