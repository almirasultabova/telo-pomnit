## Экраны и навигация

### Схема переходов

```
screen-splash
    ↓ (после входа и параллельной загрузки данных; минимальная пауза 250 мс)
screen-onboarding  (только первый запуск)
    ↓
screen-home  ←──────────────────────────────────────────┐
  [вкладка: дневник]                                     │
    → screen-body-map → screen-sensations → screen-note → screen-saved
    → screen-history                                      │
    → screen-ai-chat (AI-ассистент)                       │
  [вкладка: мой путь]                                    │
    (резюме потока, зеркало недели, график чекинов,       │
     карта тела с фильтром по неделям, топ ощущений,      │
     последние заметки, статистика — всё внутри вкладки)  │
  [вкладка: мой поток, внутренний ID profile]             │
    (расписание, ведущие, чат, zoom — внутри вкладки)    │
    → screen-meeting-detail (bottom sheet)  ─────────────┘
    → #q-invite-sheet (bottom sheet, 10с после входа)
    → screen-questionnaire (пошаговая анкета, 6 блоков)
    → screen-feedback (обратная связь по приложению)
```

### screen-feedback — обратная связь

Открывается из вкладки «Мой поток» (внутренний ID `profile`) по кнопке «Обратная связь». Содержит 5 звёздочек оценки (опционально), textarea (до 2000 символов) и кнопку «Отправить». При успехе показывается экран благодарности.

API: `POST /feedback { rating?: 1-5, text }` под `requireAuth`. Отзыв сохраняется в БД (модель `Feedback`) и сразу шлётся уведомление администраторам в Telegram (через `notifyAdminsAboutFeedback` в bot.js, рассылка по `ADMIN_TELEGRAM_IDS`). Просмотр отзывов — в админ-панели (`/admin`).

### Функция навигации

```javascript
goTo('screen-id')        // перейти вперёд
goTo('screen-id', true)  // перейти назад (анимация обратная)
goBack()                 // вернуться на предыдущий экран (из стека)
```

Стек экранов хранится в `screenStack[]`. Кнопка BackButton Telegram вызывает `goBack()`.

Срок перехода старых аккаунтов — 29 сентября 2026, 16:00 МСК, не продлевается при входе. Старые диалоги загружаются из `/ai/sessions` только для владельца.

Закрытые приглашения в data.js/index.html не возвращать. Не заменять историю купленной группы расписанием нового набора.

При запуске приложение вызывает `Api.auth()` → `POST /auth/telegram`.
Токен JWT сохраняется в `localStorage` под ключом `tp_jwt`.
Доступ к AI-ассистенту проверяется через `GET /me/enrollment/access`.

## Аналитика «Мой путь»

Вкладка `diag` рендерится через `renderMyPathTab()` → сначала блок диагностики, затем аналитика:

### Диагностика паттерна (вверху вкладки)

| Функция | Что делает |
|---|---|
| `renderDiagBlock(result)` | Если результата нет — приглашение пройти тест; если есть — карточка паттерна |
| `startDiag()` | Сбрасывает ответы, запускает квиз |
| `showDiagQuestion()` | Рендерит текущий вопрос с прогресс-баром |
| `pickDiagAnswer(pattern)` | Записывает ответ; на последнем вопросе считает результат и сохраняет через `Storage.saveDiagResult()` |

Результат: `{ patternId, date, scores }` — сохраняется в `tp_diag_result` и синхронизируется с сервером.

### Аналитика (под диагностикой)

| Функция | Что делает | Условие показа |
|---|---|---|
| `renderStreamSummary(entries)` | Итоговая карточка с цифрами потока | После 15 мая 2026 |
| `renderMirrorCard(entries)` | Зеркало недели — топ зона + ощущение за 7 дней | Всегда |
| `renderCheckinChart()` | SVG-график «Напряжение» и «Ресурс» по неделям 1–5 | Если ≥ 2 чекина в разных неделях |
| `renderHeatmapSection(entries)` | Карта тела с фильтром по неделям (Все / Н1–Н5) | Всегда |
| `renderTopSensations(entries)` | Топ-3 ощущений за выбранный период | Всегда |
| `renderRecentNotes(entries)` | Последние 3 заметки из дневника | Если ≥ 2 записей с текстом |
| `renderPathStats(entries)` | Дней в дневнике / встреч / стрик | Всегда |

**Фильтр карты по неделям:** `heatmapWeek` (глобальная переменная, 0 = все, 1–5 = неделя).  
**Хелперы:** `getStreamWeek(dateStr)` → номер недели 1–5 или null; `avgOf(arr)` → среднее.

## Анкета участницы

Пошаговая анкета (6 блоков, 21 вопрос) заполняется до начала потока.

**Флоу:**
1. После авторизации вызывается `checkAndShowQuestionnaire(streamId)`
2. Проверяется статус на сервере: `GET /questionnaires/:streamId`
3. Если не заполнена — через 10 секунд показывается `#q-invite-sheet` (bottom sheet)
4. Пользователь может закрыть sheet и заполнить позже через баннер в профиле
5. После отправки: `POST /questionnaires/pre` → флаг `tp_questionnaire_done = 'true'`

**Бот-напоминания:**  
Cron в `bot.js` (10:00 МСК) отправляет уведомления на 1-й, 3-й и 5-й день если анкета не заполнена.

**Блоки анкеты:**
| № | Тема |
|---|---|
| 1 | Демография (возраст, деятельность, город) |
| 2 | Как узнали о программе (источник, соцсети) |
| 3 | Запрос к телу (основная проблема, хронические симптомы) |
| 4 | Текущее состояние (стресс, сон, тело) |
| 5 | Ожидания от программы |
| 6 | Предпочтения и технические детали |

## Где менять данные

### Расписание встреч
Актуальное расписание своего потока приходит из API `Stream/Meeting` через `/me/enrollment/access`. Его создают и изменяют на сервере для конкретного потока. Публичный анонс следующей группы не заменяет купленный поток или его архив.

Файл [js/data.js](js/data.js), массив `DATA.program.schedule`, содержит историческое расписание для старой аналитики. Не переписывайте его датами нового набора. Пример исторической записи, не инструкция создания нового потока:
```javascript
{
  id: 1,
  date: '2026-03-26',       // ISO дата
  time: '18:00',            // МСК
  type: 'Психосоматический разбор',
  week: 1,
  practice: null,           // или 'Лёжа: Даосские пульсации'
  desc: 'Описание встречи',
  prepare: 'Как подготовиться'
}
```

### Зоны тела
Файл: [js/data.js](js/data.js), массив `DATA.zones`

Текущие зоны (фронт): голова (`head`), глаза (`eyes`), челюсть (`jaw`), горло (`throat`), грудь (`chest`), плечо лево/право (`shoulder_l/r`), верхняя рука лево/право (`arm_upper_l/r`), нижняя рука лево/право (`arm_lower_l/r`), живот (`belly`), диафрагма (`diaphragm`), таз (`pelvis`), бедро лево/право (`thigh_l/r`), голень лево/право (`shin_l/r`).

Текущие зоны (зад): затылок (`head_back`), верхняя спина (`upper_back`), поясница (`lower_back`), ягодицы (`glutes`), задняя нога лево/право (`leg_back_l/r`).

### Ощущения (13 типов + пользовательские)
Файл: [js/data.js](js/data.js), массив `DATA.sensations`

Вместо emoji используются inline SVG-строки (поле `emoji`). Рендерятся через innerHTML.
Текущий список: зажатость, тяжесть, пульсация, онемение, жжение, дрожь, пустота, тепло, боль, давление, покалывание, холод, сухость.

> При добавлении нового ощущения — поле `emoji` должно быть SVG-строкой с классом `icon-svg`, не текстовым символом.

**Пользовательские ощущения.** На экране `screen-sensations` под сеткой есть инпут «Своё ощущение». Введённое слово (до 24 символов, lowercase) сохраняется в `localStorage.tp_custom_sensations` и в дневник пишется как id `custom:<label>`. Везде, где раньше резолвился id через `DATA.sensations.find(...)`, теперь используется хелпер `getSensation(id)` из [js/app.js](js/app.js) — он понимает и встроенные id, и формат `custom:<label>`. Иконка для кастомных — нейтральный кружок (`CUSTOM_SENSATION_ICON`).

### Паттерны выживания (4 штуки)
Файл: [js/data.js](js/data.js), объект `DATA.patterns`

Текущие паттерны: `freeze` (Замирание), `fawn` (Угождение), `fight` (Нападение), `flight` (Бегство).
Поле `emoji` — inline SVG, рендерится через `innerHTML` (не `textContent`).

### Общие сведения и медиа
Файл [js/data.js](js/data.js), объект `DATA.program`, содержит общие сведения о ведущих и исторические данные. Права, актуальные встречи и закрытые ссылки предоставляет API; публичные файлы не должны содержать приглашения в закрытый чат.

Медиа приложения находятся в `../media/app/`, общие портреты — в `../media/shared/`. Пути в коде начинаются с `/media/`; сборщик переносит только необходимые публичные ресурсы. Не складывайте документы или исходники в эти публикационные папки.

### Добавление нового экрана

1. В `index.html` добавить `<div class="screen" id="screen-новый">...</div>`
2. В `app.js` добавить функцию рендера и вызов `goTo('screen-новый')` в нужном месте
3. Стили — в `styles.css`

### Онбординг — размеры и скролл

Экран `#screen-onboarding` имеет собственный `overflow-y: auto` (в отличие от остальных экранов, где скроллится дочерний `.screen-scroll`). Причина: контент (иконка + заголовок + 3 буллета + чекбокс согласия + кнопка) может не влезать на маленьких телефонах (iPhone SE, 375×667).

`.onboarding-wrap` использует `justify-content: flex-start` и компактные отступы (`padding: 24px 20px 32px`, `gap: 8px` между буллетами), чтобы на стандартных экранах контент помещался без прокрутки и кнопка «Начать» была сразу видна.

## Деплой

Beget VPS — статика отдаётся через nginx с `/var/www/telo-app/`.
URL: `https://app.telo-pomnit.ru`

J-199, 5 октября: основной запуск из бота — `https://tg-app-telo-pomnit.vercel.app/?v=startup-20261005`; Beget-адрес сохранён для прежних кнопок. Клиент использует относительный `/api`: на Vercel это rewrite к существующему API, на Beget — nginx proxy к 127.0.0.1:3000. Конфигурации — app/vercel.json и deploy/nginx/app.telo-pomnit.ru.conf. Не публиковать API_URL='/api' без соответствующего proxy.

Сборщик встраивает CSS и все JS (включая SDK/boot.js) в output/app/index.html: запуск не требует отдельных запросов к этим файлам. Исходники остаются отдельными. boot.js предоставляет AppLocalStorage с временным запасным хранилищем при недоступности localStorage; постоянное хранение тогда обеспечивает сервер после успешного сохранения. Сигнал Telegram.ready вызывается сразу после SDK; AppBoot завершает ожидание при открытии экрана, показывает ошибку/повтор при сбое или долгом соединении. scripts/test-app-startup.py проверяет Chromium/WebKit с фикстурами API; APP_TEST_BASE_URL позволяет проверить опубликованную страницу, но не подтверждает настоящий Telegram/VPN.

Из корня репозитория выполните `node scripts/build-static.mjs`, затем `powershell -NoProfile -File scripts/check-structure.ps1 -Built`. Публикуется содержимое `output/app/`, включая `media/app/`, `media/shared/` и общую админку. Полная инструкция — [Развёртывание](../База%20знаний/Техническое/Развёртывание.md). `git push` сам по себе Beget не обновляет.

SDK `js/telegram-web-app.js` хранится локально: 26 сентября 2026 восстановлена уже используемая серверная копия. При последующем обновлении сначала сохраните и проверьте локальный файл, затем пересоберите приложение. Правка SDK только на сервере приведёт к расхождению исходников и следующего деплоя.

Для теста соберите проект и запустите HTTP-сервер с корнем `output/app/`, например из корня репозитория: `python -m http.server 8081 --directory output/app`. Откройте `http://localhost:8081/`. Прямой `file://` не поддерживает пути `/media/...`. Вне Telegram можно проверить интерфейс с заглушкой/моками, но реальную авторизацию и платные права это не подтверждает.

## Известные проблемы

> **Белый экран на телефоне (2026-08-24).** В мобильном WebView Telegram (проверено на iOS)
> `height: 100%` на `html, body` схлопывался в 0 — страница технически рендерилась, но была
> невидима. На Desktop Telegram баг не проявлялся. Не лечится сбросом кэша/переоткрытием
> приложения — это не кэш. Исправление: `css/styles.css` → `html, body { height: 100dvh; }`
> (в дополнение к `height: 100%`, как фолбэк для браузеров без `dvh`). Если белый экран
> повторится — сначала проверь, не пропало ли это правило при правках `styles.css`.

> **Неполное восстановление данных с сервера (2026-08-24).** `Storage.initFromApi()`
> (вызывается при каждом старте приложения) подтягивал с сервера только дневник и
> результат диагностики. Чекины и записи «Стоп-реакция» — сохранялись на сервер, но
> никогда не восстанавливались обратно. Если у пользователя очищался `localStorage`
> (переустановка Telegram, чистка кэша, смена устройства) — эти два раздела выглядели
> пустыми, хотя на сервере данные были целы. Исправлено: `initFromApi()` теперь также
> вызывает `Api.getTriggers()` и `Api.getCheckins()`. Ограничение: сервер хранит чекин
> только как одну усреднённую оценку (`bodyScore`), а не 5 исходных ползунков
> (напряжение/тревога/энергия/безопасность/контакт с телом) — восстановленные старые
> чекины дают верный тренд на графике, но не точные значения по каждой шкале. Если нужна
> полная точность — потребуется миграция `checkins` в БД (добавить 5 отдельных полей).
