# J-APP-094 — рабочая история Дневника

18 октября 2026. Альмира приняла просмотр J-APP-093 и поручила перенос, реальные записи, сохранение «Важного» и выпуск с резервной копией. T-APP-010, продолжение I-030. OpenAI и тестовые уведомления не используются.

Дневник → История записей: поиск по всей собственной серверной истории, период, тип, Все/Важное, звёздочка, полная запись и возврат с сохранёнными фильтрами. В одной истории видны телесные наблюдения, оценки, реакции, заметки после разбора/практики. Типы исходных записей сохраняются. PDF телесных наблюдений остаётся доступен прежней кнопкой PDF; новые типы не добавлены в PDF молча.

## Данные и права

POST /diary-history/search получает запрос в JSON-теле, чтобы фразы не попадали в URL/access-log. Четыре таблицы объединяются только после ограничения userId проверенным JWT. Поиск по словам и видимым текстовым полям выполняется до пагинации, параметризован; проценты/подчёркивания считаются буквальным текстом. Период включителен, день определяется по Москве; у заметок встречи — сохранённая дата встречи. Время создания подписано «Записано», чтобы не выдавать его за время встречи.

GET /diary-history/:source/:id открывает собственную запись. PUT .../important принимает желаемое true/false, проверяет существование собственной записи под прежней блокировкой User и сохраняет одну строку по userId/source/entryId. Повторы идемпотентны; совпавший UUID у тела/оценок не смешивает отметки. Источник meeting стабилен при смене разбор/практика.

Добавочная таблица diary_important, без изменения существующих записей. FK на User и CHECK допустимых источников; полиморфная ссылка на исходную запись проверяется приложением. Отдельных пользовательских удалений исходных записей сейчас нет; полное удаление аккаунта очищает и отметки. При добавлении удаления одного типа в будущем нужно включить удаление соответствующих отметок. Собственная JSON-выгрузка содержит diaryImportant; ведущие не получают чужие дневники или отметки. Допуск и платные права не расширены, AI-контекст прежний. Все новые ответы private/no-store.

Клиент не хранит истину «Важного» в localStorage. Изменение показывается после проверенного ACK, сбой даёт повтор; после потерянного ответа повторяется явное значение, а не обратное переключение. Более старый поиск и ответы прежнего аккаунта не заменяют актуальный экран. При сбое полной истории можно открыть прежние телесные записи на устройстве, с честной подписью об ограничении. Поиск и полные серверные отметки требуют соединения.

Реальные routes/auth/GDPR: поиск после первой сотни, AND/ё/буквальные %_/SQL-ввод, даты МСК, пять типов, периоды, чужая/ведущая изоляция, 12 конкурентных повторов, коллизия UUID, смена вида встречи, экспорт/удаление только своего аккаунта.

- Статическая структура 54 HTML/CSS/JS: ошибок и предупреждений 0. Просмотрены реальные кадры принятой композиции.

При первом SQL-прогоне найден и исправлен конфликт алиаса day; финальная версия прошла PostgreSQL. Зависания ранней проверки UI были в тестовом Playwright-присваивании async-функции: заменены callback-вызовами; это не было ошибкой приложения.
