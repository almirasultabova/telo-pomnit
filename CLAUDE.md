4. Явное новое решение владельца или уточнение им смысла внеси в основной раздел: перепиши устаревшую формулировку, а не только добавь протокол внизу. Если существенное противоречие нельзя разрешить по контексту, запиши открытый вопрос и уточни только его, продолжая остальные обновления.

Позицию владельца о методе сохраняй как позицию; научные/медицинские утверждения не становятся доказанными только потому, что прозвучали в разговоре.
7. После изменения проверь зависимые документы: программу, аудиторию, роли, контент, редакцию сайта, приложение и план. Согласуй актуальные внутренние описания, убери противоречащую старую формулировку из действующих разделов. Исходные цитаты и исторические записи не переписывай.
8. Различай новое описание и текущую реализацию. Изменение видения не делает функцию реализованной и не публикует сайт. Для изменения публичного текста сохраняй предложенную замену и статус в «Редакция сайта»; пока HTML не обновлён, не называй документ точным снимком страницы. Нужные изменения кода, публикации и процессов заноси в «План» с причиной и следующим шагом; действующие границы согласования сохраняются.
9. Для каждого смыслового изменения оставляй проверяемую связь: что было → что стало → почему → источник → обновлённые документы → что ещё требуется. Детали — в «08 Решения», рассуждения — в «Журнал обсуждений», без второй копии всей спецификации. Обновляй существующую идею/задачу вместо дубликата.
10. Перед ответом сверь внесённые изменения с источником и связанными документами. Коротко сообщи уже сделанное: «Обновила X и Y; прежнее Z заменено; следующий шаг — T-...». Если что-то не удалось сохранить, назови точную причину и незавершённую часть. Не обещай сохранение неизвестных чатов и файлов, к которым нет доступа.

## Структура и источники истины

- `site/` — публичные HTML-страницы. Каждая страница самодостаточна: CSS и JS внутри.
- `app/` — Telegram Mini App; дополнительные инструкции в `app/CLAUDE.md`.
- `backend/` — API, бот, Prisma; существующий стек сохраняется.
- `media/site/`, `media/app/`, `media/shared/` — публичные медиа. Пути в коде начинаются с `/media/`.
- `media/library/` — частные исходники, визуальные варианты и старые медиа.
- `База знаний/` — основные документы по темам. Оригиналы — `Источники/`, прежние редакции — `Архив/`, эксплуатация — `Техническое/`.
- `archive/` — старые HTML и прототипы; не часть сборки.
- `output/` — пересоздаваемые сборки и результаты проверки; не редактировать как исходники.

Не сохраняй картинки, черновики и отчёты в корне. Не копируй один факт в несколько «главных» документов. Ссылки на первоисточник предпочтительнее параллельных редактируемых копий. Не переименовывай и не переписывай исходные отзывы.

## Ограничения интерфейса и визуальный стиль

Для сайта — чистые HTML/CSS/vanilla JS, без фреймворков, CDN, Google Fonts или библиотек анимации. Иконки — inline SVG. Не добавлять зависимости без задачи на это.

Шрифты: заголовки `Georgia, 'Times New Roman', serif`, текст `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`.
Палитра: крем `#f7f4ef`, зелёный `#2a4a38`, золотой `#c49a3c`, текст `#1a110a`.

Согласованная основа первого экрана — тёмно-зелёный фон и бант `media/site/concept-ribbon.jpg` с мобильной версией. Сохранять композицию по прямому пожеланию Альмиры. CSS-брейкпойнты 768px и 480px обязательны: сетки в одну колонку, меню-гамбургер на ≤768px, кнопки на полную ширину на ≤480px, шрифты через clamp(). Проверять 375px и 768px.

Анимации: CSS keyframes для фона/дыхания, IntersectionObserver для reveal, transition для hover. Не использовать Canvas для простых эффектов.

Текст: русский, «вы» с маленькой буквы, тёплый прямой тон, короткие предложения, «ёлочки», без искусственной срочности и восклицательных заголовков. Не выдумывать слова участниц, причины симптомов и доказательства результата.
