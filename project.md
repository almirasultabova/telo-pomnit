# Тело помнит — карта проекта

Обновлено: 26 сентября 2026. Эта папка — единое хранилище Obsidian, исходников сайта и приложения.

## С чего начинать

Откройте [главную базы знаний](База%20знаний/00%20Главная.md).
Основные сведения о продукте редактируются в [Продукте и программе](База%20знаний/01%20Продукт%20и%20программа.md).
Текущие задачи — в [Плане](База%20знаний/План.md).
Все идеи — в [Идеях и развитии](База%20знаний/Идеи%20и%20развитие.md), мысли и причины решений — в [Журнале обсуждений](База%20знаний/Журнал%20обсуждений.md). Во время работы сохранять новые идеи и поручения сразу, перед ответом проверять полноту, при следующем заходе возвращаться к незавершённым задачам. Постоянный порядок закреплён в AGENTS.md и CLAUDE.md.
Перед содержательной работой выполнить `powershell -NoProfile -File scripts/sync-nastya.ps1`.

Разговоры и присланные транскрибации обрабатываются как источник обновлений действующей базы. Новое принятое видение, смысл или определение сразу заменяет устаревшую формулировку в основном документе темы; причина и источник сохраняются в решениях. Связанные документы сверяются в той же сессии. Подробный порядок — «Живая база» в AGENTS.md / CLAUDE.md. Доставка транскрибации сама по себе не делает все высказанные варианты принятыми решениями.

## Где что находится

| Папка | Назначение |
|---|---|
| `site/` | Семь самостоятельных HTML-страниц: основной лендинг, гайд, оферта, политика, спасибо, админка, презентация |

| `media/app/` | Изображения приложения |
| `media/shared/` | Общие портреты, один исходник для сайта и приложения |

| `База знаний/` | Один основной документ на каждую тему; карта — «00 Главная» |
| `База знаний/Источники/` | Оригинальные материалы владельцев; источник фактов, не параллельная рабочая редакция |
| `База знаний/Архив/` | Прежние планы, редакции и история решений |
| `База знаний/Техническое/` | Развёртывание и проверка систем |
| `archive/` | Старые HTML-версии и экспериментальный прототип дневника |
| `scripts/` | Проверка структуры, сборка для публикации и получение изменений Насти |
| `deploy/` | Конфигурация серверного окружения |
| `output/` | Пересоздаваемые сборки и проверки; не источник материалов |

## Совместная работа с Настей

26 сентября по поручению Альмиры новая структура отправлена в GitHub `main`. Структурный коммит `8b3e0f0`, объединение истории `86bf02f`; удалённый SHA проверен через `git ls-remote`. Содержание отвергнутой версии (7 коммитов до `0f762f7`) не перенесено: в актуальном дереве нет `landing_live.html` и `.impeccable/config.json`. Рабочая страница — `site/landing_final.html`; история сохранена без force push. Проверка ветки Насти не заменяет сверку `main`. Beget этой синхронизацией не обновлялся; редакция сайта по-прежнему требует принятия.

Репозиторий публичный. Личная медиатека `media/library/`, материалы «Личного бренда», секреты, настройки Obsidian и результаты проверок остаются локально/в резервных копиях согласно `.gitignore`; это намеренное отличие от полного локального хранилища. Новые транскрибации проверять на личные данные перед любым будущим push.

Ветка источников: `origin/nastya/collaboration-check`; последний перенесённый снимок — `ce10f4208ca684436c885e3e0e53583f942318c4`.
Оригиналы находятся в `База знаний/Источники/Анастасия/`. Содержание относится к практикам и психосоматическим разборам; файл `PSYCHOSOMATIC_REVIEWS_TEXT.md` не является подборкой отзывов.

Задача Windows `TeloPomnit-NastyaSync` получает изменения каждые 15 минут, когда компьютер доступен. Она выполняет fetch и сохраняет технический статус внутри Git. Смысловое встраивание выполняет агент во время работы: читает различия, обновляет основной документ темы, проверяет связанные места и отмечает точный коммит обработанным. Отдельные «Входящие» не создаются.

## Сборка и публикация

```powershell
powershell -NoProfile -File scripts/check-structure.ps1
powershell -NoProfile -File scripts/build-static.ps1
powershell -NoProfile -File scripts/check-structure.ps1 -Built
```

Сайт для загрузки: `output/site/`; приложение: `output/app/`.
Инструкция — [Развёртывание](База%20знаний/Техническое/Развёртывание.md). На сервер загружается содержимое сборки; URL страниц и домены остаются прежними. `git push` сам по себе не обновляет основной продакшн на Beget.
