## Найдено и исправлено

В исходном полном аудите отдельно оставлялась сохранность редактирования личного шага при уходе. В действующем after-meeting.js поле ps-edit-text имело только обработчик доступности кнопки; повторное открытие заново подставляло row.stepText. Потеря введённой правки воспроизведена на опубликованной версии J-APP-151, не выведена только из кода.

Правка теперь хранится через существующий owner-scoped Storage.saveFormDraft с отдельной областью step-edit-v1:<id>. Вместе с текстом сохраняются исходная формулировка и revision. Возврат и перезагрузка восстанавливают редактор. Рядом с полем прямо объяснено: это правка на устройстве, сам шаг изменится только по «Сохранить шаг». При запрете записи показано хранение только в открытом приложении. Автоматической отправки нет.

Если серверный шаг изменился, сохранённый текст и местная правка показаны рядом; сохранение недоступно до явного «Продолжить с этим текстом». Это подтверждение только местного текста: API вызывается следующим отдельным нажатием «Сохранить шаг». Ошибка версии→обновление записи также сохраняет правку.

Черновик очищается только явным «Убрать правку» либо подходящим серверным ACK именно этой версии/формулировки/записи. При неудачном удалении на устройстве используется существующий null-tombstone и честное сообщение. Неподходящий ACK/поздний ответ другого аккаунта не очищает черновики. Обычный черновик наблюдения после шага и остальное хранение не менялись.

Визуально: поля и кнопки остаются в действующей природной системе; кнопки шага приведены к общим52px/16px, подпись черновика имеет читаемый цвет на шалфейной поверхности. В конфликте главным действием становится подтверждение текста; кнопка сохранения появляется после него. После явного удаления фокус возвращается к действию редактирования. Изменены только два существующих исходника: after-meeting.js/css; backend, контракты API и зависимости прежние.
