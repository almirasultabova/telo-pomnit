# J-APP-065 / A14 — карточка участницы и права: локально исправлено

**Текущий этап J-APP-066:** исправление опубликовано по отдельному прямому поручению; [выпуск и backup](../participant-release-JAPP066/RELEASE.md). Ниже — исторический срез локальной проверки J-APP-065.

17 октября 2026. Альмира разрешила проверку карточки/прав и исправление при подтверждении ошибки: только искусственные данные, без настоящих участниц/уведомлений, **не публиковать**. Следующий этап J-APP-064 разрешён этим поручением. Изменения локальные; commit, push, деплой, миграции и обращения к рабочей БД не выполнялись.

## Где была ошибка и используется ли маршрут

`GET /admin/participants/:id` в backend/src/routes/admin.js возвращал весь Prisma User, включая BigInt telegramId. На настоящем Fastify с реальной JWT-проверкой и искусственной read-only БД воспроизведён **HTTP500, Do not know how to serialize a BigInt**. Исходник до правки совпадал с опубликованным release-клоном по тексту; сохранён в output/participant-card-JAPP065/admin-before.js. Повторяемая команда `node scripts/test-participant-card.cjs --baseline` запускает этот сохранённый модуль с нормальными относительными зависимостями и теми же изолированными данными.

Поиск по действующим app/, site/ и backend/src не нашёл клиента подробного legacy-маршрута. site/admin.html вызывает `/admin/participants` для таблицы, без открытия `/:id`. Нынешний «Профиль → Управление» получает список `/access-admin/users`; решение по доступу открывает через `/access-admin/actions`. Обзор потока использует `/stream-overview`. Поэтому ошибка старого API подтверждена, но она не доказана как причина сбоя нынешней панели управления. Новую кнопку карточки или интерфейс в этом этапе не добавляли.

## Что изменено

В одном обработчике backend/src/routes/admin.js:

- Вместо полного User — явный select идентификации/контакта, роли, даты регистрации и прежних связанных данных. tokenVersion, тексты согласия, внутренние lease/notification-поля, настройки и любые будущие поля User автоматически в ответ не попадают.
- telegramId преобразуется через String(), без промежуточного Number: искусственное 9007199254740993n выдаётся точно как строка.
- Нет кэширования персонального ответа: `Cache-Control: private, no-store`.
- Несуществующий и удалённый аккаунты дают одинаковый 404; служебная метка deletedAt не выдаётся.

Граница requireAdmin осталась прежней: это owner-only маршрут по подтверждённому ADMIN_TELEGRAM_IDS, а не новая привилегия роли ADMIN или HOST. Прежние данные зачислений, анкет и последнего legacy-результата для владельца сохранены; свободные ответы анкет не открывались новым ролям. Дневники и AI-разговоры не включены в карточку. Остальные маршруты, схема и авторизация не менялись.

Дополнены tests: новый scripts/test-participant-card.cjs и адаптация scripts/test-host-access.cjs. Старый HOST-тест сначала остановился до проверок из-за отсутствующей в его fixture зависимости app-visits, добавленной ранее J-APP-057. Дополнена только карта тестовых зависимостей; методы статистики/записи посещения выбрасывают ошибку при случайном вызове. Продуктовый код посещений не менялся, тест не подменяет нужные проверки доступа.

Отдельно `node scripts/test-host-access.cjs`: 6 случаев бессрочного служебного доступа и 3 границы администрирования PASS. Syntax обеих тестовых программ/исправленного маршрута и git diff --check PASS.

Побочных действий нет: fixture целиком равна начальному снимку, записей в БД **0**, внешних fetch **0**, обращений к AI-провайдеру **0**, уведомлений **0**. Реальный db-модуль перехвачен до импорта, .env не загружается, все write-методы запрещены. OpenAI-конструктор заменён заглушкой; HTTP-порт Fastify не открывается, используется inject. Прежние PostgreSQL-тесты с загрузкой .env намеренно не запускались. Физический телефон не нужен для этих серверных проверок.
