# Повтор выбранной истории — J-APP-115 / T-APP-025

19 октября 2026. После разрешённого выпуска J-APP-112 → J-APP-114 продолжена локальная работа над лишними запросами больших дневников. При проверке найден конкретный случай: отказ истории состояний заставлял кнопку повтора снова скачивать весь уже готовый дневник. Более того, один общий незавершённый bootstrap мог удерживать повтор другой истории. Это следующий ограниченный этап; сокращение первичной полной загрузки не реализовано.

В app/js/storage.js initFromApi принимает необязательные fields: diary/checkins/diagnostic/habitual. Без аргумента сохраняет первоначальную загрузку всех четырёх ресурсов. Явный пустой набор не создаёт запросов, неизвестное имя отклоняется. Статус loading/loaded/failed меняется только у запрошенной истории. Один незавершённый запрос объединяется по владельцу, поколению и ресурсу даже при пересекающихся наборах; отдельный повтор готов раньше незавершённого соседнего запроса. Поздний ответ другого владельца игнорируется. Прежнее слияние с кэшем/очередью и защита пустого GET сохранены.

В app/js/app.js повтор на Главной выбирает текущие failed-истории; предупреждение Дневника/истории состояний повторяет только соответствующий ресурс. Повтор графика запрашивает только checkins. Тексты, кнопки, палитра, дизайн, пять шкал и вычисления сохранены. Backend/API-контракт/база/AI/наличные не менялись.

## Проверено

- 8 targeted Storage-групп: 2000 готовых записей дневника остаются при повторе только checkins; повторных запросов дневника/опросов 0. Пересекающиеся наборы объединяются, незавершённый опрос не задерживает отдельный повтор, пустой выбор/неизвестный ресурс, смена владельца, ошибка/пустой GET и pending-очередь проверены. Все запущенные загрузки в тесте завершены, обе карты незавершённых запросов пусты.
- 32 браузерных сценария Chromium 320/390/1440 и WebKit 390. Главная повторяет только отказавшие состояния; 205 готовых записей и прежние три GET дневника сохраняются. Дневник восстанавливает все 205 строк тремя страницами, пока исходный checkins ещё удерживается; затем завершается единственный соседний запрос. Ошибка снимается отдельно, график обновляет только checkins. Реакции остаются отложенными, PageErrors/overflow нет.
- Повторены 36 прежних UI-сценариев J-APP-112, 11 Storage-групп и проверка очередей/офлайн/ограниченного хранилища/смены владельца. Исходный bootstrap без fields сохраняет прежнее поведение.
- Изолированная сборка от чистого опубликованного кода плюс только два новых исходника: 45 site/88 app. Структура 58 HTML/CSS/JS, без предупреждений. Меняются четыре публичных артефакта: index.html, screen-review.html, js/app.js и js/storage.js; панель наличных сохранена.
- Учебный просмотр использует отдельную копию исходников этой сборки: 205 вымышленных записей и один отказ состояний. Отдельный Chromium 390 подтвердил ошибку → повтор → loaded с теми же 205 записями. Настоящих API/аккаунтов/данных/OpenAI/уведомлений нет.

См. ui-results.json, regression-ui.json, storage-results.json, build.json и preview-check.json. Точный diff — changes.patch. Код прошёл syntax/scoped diff. Применены karpathy-guidelines, webapp-testing и узкие правила ui-ux-pro-max о состояниях загрузки/повторе без изменения действующей айдентики.

## Статус и граница

Только локально, без коммита/push/публикации J-APP-115. В production остаётся J-APP-114 с сохранённым исправлением наличных J-APP-113. Физический Telegram не проверялся. Главная, карта, серия и графики пока используют полностью восстановленные diary/checkins; серверные агрегаты, загрузка выбранного периода и ограничение памяти — следующий отдельный этап. Этот пакет уменьшает лишнюю повторную загрузку при сбое, не объём первоначального входа.

Учебный просмотр: http://127.0.0.1:49045/app/index.html?owner=preview&v=JAPP115 . На Главной прокрутить до «Ваши наблюдения» и нажать «Повторить загрузку наблюдений». При перезагрузке учебный отказ повторяется; все записи вымышлены. Следующий шаг — оценка просмотра владельцем, публикация отдельно.
