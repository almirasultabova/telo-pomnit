# J-APP-072 — черновик трекера до сохранения

**Продолжение J-APP-073:** по отдельному поручению18октября кандидат опубликован с резервной копией; затем живой AI проверен на искусственных данных. [Выпуск и ограничения](../draft-release-JAPP073/RELEASE.md). Ниже сохранён локальный этап до согласования выпуска.

18 октября 2026. Прямое поручение Альмиры: сохранить черновик заметки и оценок; искусственные данные, без OpenAI и уведомлений. Реализовано и проверено локально. Публикация, commit и push не выполнялись.

## Поведение

- При каждом изменении заметка и все пять оценок сохраняются через существующий `Storage.saveFormDraft('checkin', ...)` в namespace подтверждённого аккаунта. При возврате и перезагрузке восстанавливаются вместо прежней сохранённой записи.
- Черновик не отправляется на сервер автоматически. «Сохранить оценки» использует прежнюю очередь и подтверждение сервера; после принятия в устойчивую очередь либо серверного подтверждения соответствующий черновик снимается. Если очередь только в оперативной памяти и отправка не удалась, черновик остаётся.
- «Удалить черновик» возвращает ранее сохранённые оценки/заметку, не удаляя историю. Используется null-маркер, чтобы скрыть предыдущую версию также в fallback памяти. При запрете записи на устройство удаление подтверждается только для открытого окна: изменить старое содержимое недоступного хранилища гарантировать нельзя.
- Запрет localStorage/ошибка записи: черновик доступен в текущем открытом приложении, есть предупреждение, что закрывать его до подтверждения сервера нельзя. Восстановление после закрытия при таком запрете не обещается.
- Аккаунты разделены; устаревший экран не отправляет ввод прошлого владельца. Удаление собственного аккаунта очищает черновик через существующий purge, чужой namespace не затрагивает.
- У черновика сохраняется исходная дата. После перехода московской даты показывается дата черновика, сохранение относится к этому дню. Повреждённые данные/неправильные шкалы не восстанавливаются.
- Запоздалый ответ сервера не снимает новый черновик, введённый во время предыдущей отправки.

## Изменения

Функциональная правка только в `app/js/app.js`: загрузка/запись черновика, статус/удаление, guards владельца и очистки после Save. Существующие `boot.js`, `storage.js`, backend, БД, провайдер, модель, уведомления и права не менялись. Исходная база app.js перед правкой совпадала с опубликованным release-клоном `6dd7940` (J-APP-071). Остальные накопленные изменения рабочего дерева не включались в патч. Отдельный diff от чистого выпуска: `output/checkin-draft-JAPP072/app.patch`.

## Проверка

Изолированная копия действующего frontend на `127.0.0.1:8919`; повторно использован fixture J-APP-069 с настоящими auth/schema/checkin handlers и искусственной БД в памяти. SDK/заставка/логин/время учебные, Telegram и реальные ключи не используются. Серверный fetch заблокирован; браузер пропускает только локальный origin. Генерации OpenAI, внешние вызовы и уведомления: 0; настоящие участницы/данные не менялись.

`check.py`: Chromium и WebKit × доступное/запрещённое хранилище — четыре PASS. Всего 26 последовательных сценариев: уход/возврат с пятью оценками и заметкой без серверной записи; reload при доступном хранилище; смена аккаунта и устаревший Save; удаление; явный Save/ACK; изменение поверх сохранённой записи; purge одного владельца с сохранением другого. `output/checkin-draft-JAPP072/results.json`.

`edges.py`: на исходнике выпуска до правки воспроизведён сброс заметки и оценки через обычную кнопку входа в трекер. На новой версии Chromium с обоими режимами хранения проверены повреждённый черновик, прежняя московская дата, запоздалый ACK с новым вводом, искусственный HTTP503 без ложного успеха. Все PASS, `output/checkin-draft-JAPP072/edges.json`.

Первый запуск тестового harness потребовал функции-предиката вместо строки из-за CSP; продукт не менялся по этой причине. Один WebKit-прогон прервался при закрытии соединения с драйвером, затем адресно повторён и прошёл; три готовых сочетания без причины не повторялись. Скриншоты основного статуса/предупреждения — `output/checkin-draft-JAPP072/*-draft-*.png`; основной статус визуально просмотрен. `node --check app/js/app.js` и `node scripts/build-static.mjs` успешны, сборка приложения 80 публичных файлов. Сборка не является публикацией.

## Граница результата

Это браузерная проверка локального кандидата, не физический тест Telegram/iPhone/Android. Черновик остаётся на том устройстве, где начат; перенос между устройствами не добавлялся. При полном запрете хранения после закрытия восстановление невозможно, о чём сообщает UI. Настоящий AI не вызывался; сообщение Альмиры об оплате OpenAI зафиксировано отдельно, зачисление/ответ API ещё не проверены. Локальный fixture остановлен после проверки.

Следующий шаг: отдельное решение владельца о выпуске с резервной копией, затем физическая проверка Telegram.
