# J-APP-112 / T-APP-023 — вторичные истории по обращению

18 октября2026. Следующий локальный пакет по прямому продолжению Альмиры в J-APP-111. Предыдущий J-APP-110 уже опубликован отдельно; этот пакет автоматически не включён.

В app/js/storage.js bootstrap больше не вызывает GET истории реакций. Он сохраняет её отдельный текущий статус; повторное восстановление diary/checkins не сбрасывает уже загруженную историю. bindUser начинает новый цикл состояний idle для нового поколения авторизации, чтобы прежний кэш не считался свежей проверкой сервера в новой сессии. Кэш/очереди не удаляются. flushTriggersPending остаётся фоновым и не требует открытия истории.

В app/js/app.js вход в экран истории реакций при idle запускает существующий loadTriggerHistory, который читает все страницы, имеет собственные loading/error/retry и защиту владельца. Повторное открытие подтверждённого списка в той же сессии не запускает лишний скан. Ошибка не выдаёт первую страницу за полную историю; загруженный кэш сохраняется с предупреждением. AfterMeeting.refresh вызывается при реальном входе в Дневник; заметки по-прежнему показываются там полностью с действующим «Показать ещё». Main/Profile не скачивают их заранее. Модуль «К разбору» уже загружался по обращению и не менялся.

При проверке выхода найден прежний крайний случай: загруженные карточки реакций оставались в скрытом DOM после Api.logout. В app/js/observation-drafts.js invalidate теперь очищает только trigger-history-list. Это не удаление записей или кэша; поздний ответ прежнего владельца не возвращает карточки. Исправление проверено вместе с отложенной загрузкой.

Замер на одинаковом вымышленном наборе205реакций+51заметка, прежние app.js/storage.js подставлены из snapshot перед пакетом: раньше при Main было3GET реакций(90/90/25) и2GET заметок(50/1); теперь0 и0 до открытия нужного раздела. При переходе в Дневник заметки снова читаются двумя страницами, при открытии истории реакций — тремя. На этом наборе5запросов и256записей не передаются при старте. Это не измерение времени на настоящем устройстве и не обещание такого же числа для любого аккаунта.
