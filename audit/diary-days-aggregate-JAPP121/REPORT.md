19 октября 2026. Следующий разрешённый локальный пакет после выпуска J-APP-119 в J-APP-120. Реализован и проверен: вместо передачи даты каждой записи из PostgreSQL в Node.js запрос /diary/days получает уникальные московские дни, уже отсортированные базой. Контракт ответа и интерфейс сохраняются. Кандидат не опубликован и не переносился в текущий выпуск.

Это уменьшение количества строк между базой и сервером приложения. Чтение исходных строк внутри PostgreSQL остаётся; ускорение по времени без измерения не заявляется. Индексы/миграции и ограничение полного клиентского кэша не входят в этот пакет.

## Изменение

Единственный продуктовый исходник — `backend/src/routes/diary.js`. Безопасный tagged-template Prisma `$queryRaw` передаёт userId отдельным параметром; постоянный SQL выбирает DISTINCT day, фильтрует владельца и сортирует дни. Поле Prisma DateTime хранится как UTC в timestamp without time zone: запрос сначала явно задаёт UTC, затем переводит в `Europe/Moscow`. Это сохраняет московские исторические смещения, а не фиксированный +03:00.

Ответ остаётся `{timeZone:'Europe/Moscow', days:[...]}`, авторизация прежняя, Cache-Control private/no-store; ошибка чтения — общий503 без ORM/SQL/личных данных. Тексты/ID записей не выбираются. Пять шкал, серия и клиентская догрузка остаются опубликованными J-APP-119. Новых пакетов, миграций и индексов нет.

Кандидат исполнялся из отдельного каталога; reference — установленный J-APP-119, подключённый исключительно к тестовой базе. Результаты — [postgres-results.json](postgres-results.json), код — [test-postgres.cjs](test-postgres.cjs).

- Дословное совпадение JSON-ответов старого и нового маршрутов для четырёх искусственных владельцев: исторические даты/дубликаты, другая история, пустой дневник, плотная история.
- Московские смещения 2001/2010/2011/2014 годов и границы полуночи 2026; изменение 2014 года проверено по обе стороны перехода.
- Изоляция владельцев, попытка задать SQL-подобный userId в query, pending, устаревший tokenVersion, отсутствие авторизации, private/no-store.
- Настоящий отказ SQL при временном переименовании тестовой таблицы:503 без деталей; восстановление после возврата таблицы успешно. Рабочая таблица не переименовывалась.
- На 10 000 учебных записей за пять дней количество строк результата из базы сократилось **10 000 → 5**. Размер JSON-сериализации результатов Prisma **410 001 → 106 байт**. Это размер объектов на стороне приложения, не измерение сетевого протокола PostgreSQL, времени запроса, памяти процесса или публичного ответа API. Сам публичный ответ по смыслу и байтам прежний.
- Хеш рабочего серверного исходника до/после одинаков; кандидат не установлен. Тестовых записей в рабочей базе, внешних вызовов, OpenAI/уведомлений0.

## Показ и границы

[Локальный J-APP-121](http://127.0.0.1:59697/app/index.html?owner=preview&v=JAPP121) использует изолированную сборку и503 вымышленные записи. Видимых изменений дизайна нет: пакет меняет способ получения дней сервером. Реальные API/личные записи/Telegram-уведомления в просмотре не используются.

Изменение не ограничивает чтение строк внутри самой базы, число дней в ответе, полный клиентский кэш или полную загрузку по обращению. Скорость на реальном телефоне и фактическом объёме базы не измерялась. Физический Telegram отдельно. PostgreSQL и Node.js используют собственные версии tzdata; проверенные исторические даты совпали, абсолютное совпадение всех исторических дат не заявляется.

Следующий шаг — оценка владельцем и отдельный согласованный выпуск J-APP-121. Исходник не закоммичен, не отправлен и не установлен в рабочее приложение.
