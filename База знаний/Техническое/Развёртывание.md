# Сборка и развёртывание

Актуально на 26 сентября 2026. Эта инструкция описывает структуру после упорядочивания проекта. Реорганизация локальных файлов сама по себе не публикует сайт или приложение.

## Исходники и публичные файлы

| Назначение | Исходники | Готовая сборка | Каталог на Beget |
|---|---|---|---|
| Сайт | `site/` | `output/site/` | `/var/www/telo-site/` |
| Telegram Mini App | `app/` | `output/app/` | `/var/www/telo-app/` |
| API и бот | `backend/` | отдельная сборка не нужна | `/var/www/telo-pomnit/backend/` |

Медиа находятся в `media/`: `site/` — публикационные ресурсы сайта, `app/` — ресурсы приложения, `shared/` — общие изображения. `media/library/` хранит исходники и материалы для работы; эта папка не публикуется.

Сборщик копирует только разрешённые HTML, CSS, JavaScript и медиа. База знаний, внутренние документы, PDF, история, `.env` и `media/library/` в сборку не входят. `site/admin.html` — единый исходник админки; сборщик помещает его в обе публичные сборки.

## Локальная проверка

Из корня проекта:

```powershell
powershell -NoProfile -File scripts/check-structure.ps1
powershell -NoProfile -File scripts/build-static.ps1
powershell -NoProfile -File scripts/check-structure.ps1 -Built
```

Для сборки нужен Node.js; внешние пакеты не требуются. `scripts/build-static.ps1` запускает единственный сборщик `scripts/build-static.mjs`, поэтому Windows и резервный хостинг используют один список разрешённых файлов. На другой системе или напрямую выполните `node scripts/build-static.mjs`.

Повторная сборка перезаписывает только известные публичные файлы. Если в выходном каталоге есть посторонние или устаревшие файлы, скрипт останавливается и называет точный путь. Удаления каталогов автоматически не выполняются.

Для просмотра исходников запустите HTTP-сервер из корня проекта и откройте `/site/landing_final.html` либо `/app/index.html`. Медиа используют адреса `/media/...`; прямое открытие HTML через `file://` не является проверкой корректного запуска.

Для проверки публичных адресов `/`, `/privacy`, `/guide` нужен сервер с маршрутами из `deploy/nginx/telo-pomnit.ru.conf`. Обычный локальный HTTP-сервер позволяет открыть `.html` напрямую. Для проверки каждой сборки её каталог должен быть корнем отдельного локального сервера.

Статическая проверка ищет битые ссылки на локальные ресурсы, изображения, CSS-фоны и якоря. Она не отправляет формы и не проверяет внешние сервисы. После неё требуется просмотр сайта на 375, 768 и 1440 px, проверка окон, кнопок и ошибок браузера.

## Ручной деплой после согласования

Содержимое сборки переносится непосредственно в корень соответствующего сайта на сервере. Папки `site/` и `app/` в публичные URL не добавляются. Копирование `media/` целиком из корня репозитория запрещено: там есть непубличная библиотека.

```powershell
scp -i c:/tmp/beget_key -r ./output/site/. root@45.11.93.236:/var/www/telo-site/
scp -i c:/tmp/beget_key -r ./output/app/. root@45.11.93.236:/var/www/telo-app/
ssh -i c:/tmp/beget_key root@45.11.93.236 "nginx -t"
```

Команды сайта и приложения независимы: выполняйте только нужную публикацию. Перед заменой существующих серверных файлов сохраните их резервную копию. Копирование не удаляет старые серверные файлы; их очистка требует отдельного списка точных путей и проверки восстановления.

После публикации проверьте домен в Microsoft Edge, загрузку `/media/...`, консоль и нужный пользовательский путь. `git push` не обновляет Beget автоматически. Локальную редакцию сайта нельзя считать согласованной лишь потому, что сборка прошла.

Бэкенд разворачивается адресным копированием изменённых файлов из `backend/` и `pm2 restart telo-backend`. При изменении серверных переменных окружения нужен `--update-env`. Локальный `backend/.env` не входит ни в одну публичную сборку.

## Админка и API

Основной адрес — `https://app.telo-pomnit.ru/admin.html`, резервный — `https://telo-pomnit.ru/admin`. Команда `/admin` в боте доступна только `ADMIN_TELEGRAM_IDS` и открывает Web App по `ADMIN_PANEL_URL`.

Админка авторизуется через Telegram `initData` и `POST /auth/telegram`, сохраняет JWT в `localStorage.tp_admin_jwt`; на домене приложения допускается резервный токен `tp_jwt`. Вне Telegram остаётся ручной ввод JWT. Серверный `requireAdmin` проверяет разрешённые Telegram ID; наличие кнопки или токена в интерфейсе не заменяет эту проверку.

Разделы: сводка, отзывы, анкеты, пользователи и заявки. Уведомление о доставке заявки не означает, что ведущая уже ответила. API включает `GET /admin/stats`, `/admin/feedback`, `/admin/feedback/stats`, `/admin/participants`, `/admin/questionnaires`, `/admin/questionnaires/stats`, `/admin/waitlist`.

В `backend/src/index.js` админ-маршруты регистрируются с `prefix: '/'`: сами пути уже начинаются с `/admin/`. Префикс `/admin` создаст ошибочный `/admin/admin/...`. `telegramId` из Prisma BigInt необходимо сериализовать строкой, иначе список участников вернёт 500 при `JSON.stringify`.

## CORS и мониторинг

Разрешённые origin в `backend/src/index.js` и опубликованном API: `https://telo-pomnit.ru`, `https://www.telo-pomnit.ru`, `https://app.telo-pomnit.ru`, `https://almirasultabova.github.io`, `https://web.telegram.org`, `https://tg-app-telo-pomnit.vercel.app`, `https://telo-pomnit-t6my-almirasultabovas-projects.vercel.app`. Последние два адреса — Vercel-резерв приложения.

Правьте локальный файл, затем переносите проверенную версию на VPS. Не редактируйте `index.js` серверным `sed`: следующий деплой затрёт исправление, а исчезнувший origin ломает AI-чат сообщением `Failed to fetch` / `Load failed`.

Серверный cron `0 * * * *` выполняет `/var/www/telo-pomnit/backend/scripts/health-check.sh`; локальная копия — `backend/scripts/health-check.sh`. Он проверяет HTTP 200 на `/health`, CORS preflight `OPTIONS /ai/chat` с origin приложения и состояние PM2 `online`. Для `/health` используются три попытки с паузами 10 секунд. Только после неудачи всех попыток отправляется предупреждение всем `ADMIN_TELEGRAM_IDS`; журнал — `/var/log/telo-health.log`. Telegram-текст формируется с настоящими переводами строк, а не буквальным `\n`.

## AI и раздельные права

Модель в `backend/src/routes/ai.js` — `gpt-4o-mini`. Уборка структуры не меняет модель, оплату или ограничения. Численная квота AI отдельно не согласована; безлимит не обещается.

Дневник, реакции, чекины и история наблюдений бесплатны без срока потока. Новые сообщения AI доступны в календарный период своего оплаченного потока. Собственная AI-история остаётся для чтения после окончания; записи встреч доступны ещё три календарных месяца. Срок записей независим от AI.

`getProgramAccess` в `backend/src/routes/me.js` определяет права; `GET /me/enrollment/access` возвращает права AI и потоки. `/ai/chat` проверяет доступ перед вызовом модели. `hasAccess` нельзя использовать для общей платной блокировки приложения; `canWrite` относится к AI. `/ai/sessions` и `/ai/sessions/:sessionId` возвращают только собственные диалоги без обращения к модели.

Для аккаунтов, созданных до 22 сентября 2026, 16:00 МСК, переходный доступ заканчивается 29 сентября 2026, 16:00 МСК; вход не продлевает срок. Исторические active/completed-зачисления до границы запуска сохраняются без `paidAt`; для новых требуется подтверждение оплаты `paidAt`. Отменённое зачисление не даёт переходное право. Административный доступ к AI не открывает чужие личные записи.

Расписание своего потока берётся из API `Stream/Meeting`. `DATA.program.schedule` — исторические данные старой аналитики, не источник нового набора. Повторная покупка добавляет новый поток, сохраняя дневник и предыдущую историю. Неоплаченная заявка не открывает AI, Zoom или закрытый чат; возврат отзывает соответствующие платные права, сохраняя бесплатный дневник.

Выдача закрытых Zoom/chat-ссылок контролируется API, но сервер не отзывает членство в Telegram или уже скопированные приглашения. Отдельного хранилища записей в приложении пока нет; завершение доступа к записям требует действий на внешней платформе. Подписка, продление и автоматические списания не включены. Подробная модель продукта и нерешённые вопросы находятся в тематическом документе приложения; изменения этих условий требуют отдельного решения.
