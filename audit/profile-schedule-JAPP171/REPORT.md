# J-APP-171 — понятно, обновилось ли расписание; локально

20 октября2026. Продолжение раздела6/14 исходного аудита после публикации J169→J170. Только локальная подготовка по поручению Альмиры. РежимOperate, прежние айдентика/карточки/встречи/Zoom/коды/оплата/права сохранены. Применены ui-ux-pro-max (loading/success/focus), impeccable (адресная полировка), karpathy-guidelines (два исходника) и webapp-testing.

До: вChromium/WebKit390 текст кнопки в ожидании «Обновить расписание», после успеха нет подтверждения, поле выбора и обновление оставляют управление на контейнере/BODY. Выбранный поток при этом сохранялся — его потеря не заявлялась. [Воспроизведение](baseline.json), [границы](BRIEF.md).

Теперь при обновлении кнопка показывает «Обновляем…» и блокирует повтор даже при фоновой перерисовке. При успехе рядом появляется «Расписание обновлено». Ошибка находится прямо под одним действием «Попробовать ещё раз» и объясняет, что на экране последние загруженные данные. Сами данные и выбранный поток при сбое остаются прежними.

После выбора потока сохраняется фокус на новом поле; вWebKit возврат выполняется после завершения нативного события, с проверками владельца/поколения/вкладки/выбранного потока и без перехвата другого элемента. После обновления восстанавливается действие либо поле, с которым участница уже работает. Уход с профиля не меняет вкладку/фокус от позднего ответа; смена личности очищает индикаторы, старые ответы не восстанавливают данные. API/серверная авторизация не изменялись.

Проверено:30UI-групп Chromium320/390/1440 и WebKit320/390;8краевых групп двух движков;76прежних групп отдельной встречи/участия/записи/кода/закрытия/отзыва доступа J143 на четырёх browser-width случаях.0реальных операций/генераций/уведомлений.98публичных файлов,66HTML/CSS/JS без структурных ошибок/предупреждений, syntaxJS. [UI](ui-results.json), [границы](edge-results.json), [встреча](regression/ui-results.json), [изолированность](verification.json).

По принятому формату показа: три сравнения одинаковых условий «обновляется / готово / ошибка», шесть реальных браузерных кадров, рамки/цифры/короткие подписи. Оба окна ориентированы на кнопку обновления. Рамки находятся только в странице согласования. Три переключателя, загрузка всех изображений, клавиатура и390px без overflow/JSошибок прошли. [Просмотр](http://127.0.0.1:15371/review), [проверка](marked-results.json), [пример ошибки](explained-error.png).

Во время проверки вымышленных данных исправлен сам fixture: он теперь возвращает корректное пустое состояние анкеты для второго учебного потока, чтобы посторонняя учебная ошибка не отвлекала от сравнения. Это изменение тестовых данных, не приложения. Физический телефон и весь профиль/служебные роли этим адресным пакетом не закрываются.

Изменены только app/js/app.js и app/css/ux-personal.css. Основной опубликованный checkout остаётся J169; J171 есть в отдельном кандидате/корневой рабочей копии. Следующий шаг — оценка владельцем отмеченного сравнения и отдельное решение о публикации.
