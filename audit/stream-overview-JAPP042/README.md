# J-APP-042 — рабочая интеграция обзора потока

15 октября 2026 Альмира приняла J-APP-041 и прямо поручила подключить реальные данные и опубликовать для неё и Анастасии. Публикация и необходимые аддитивные изменения схемы входят в поручение. Тестовые уведомления/письма людям запрещены.

## Контракт

- Профиль → «Обзор потока», отдельная страница в той же оболочке; JWT передаётся только через память доверенного same-origin родителя. Прямой URL без действующей сессии не открывает данные.
- Владелец видит потоки; для подтверждённого аккаунта Анастасии HOST — отдельный grant на октябрьский поток. Роль HOST сама по себе не даёт обзор. ADMIN не наследует его. Полное управление доступами не расширяется.
- Анкеты: уникальные участницы с подтверждённым зачислением, без владельца/ведущих/удалённых/явно исключённых из аналитики. Сравнение двух шкал — отдельно, полные пары pre v1/post v2. Только агрегаты и именные статусы; личные тексты анкет, дневников и AI не передаются.
- Возвращение: две полные недели с непрерывным доказанным допуском. Новые сохранения считаются по серверному `saved_at`, не по изменяемой клиентской дате. Старые записи не получают фиктивное время нового сохранения. История допуска начинается при миграции и поддерживается триггерами БД для изменения зачисления/роли/допуска/срока/удаления. Прежние недели не восстанавливаются из текущего состава.
- Обратная связь: явные поток/тема/нужен ли ответ. Старый клиент остаётся совместимым; неизвестные прежние сообщения — отдельный ручной разбор владельца. Не приписывать поток по текущему зачислению автоматически.
- Обработка: атомарный revision, назначение на себя, подтверждение фактического ответа, автор/время/журнал. Чужого ответственного нельзя перезаписать. Отметки сами не шлют ответ участнице. Контакт Telegram только при корректном доступном username; иначе честное отсутствие ссылки.
- Идемпотентность обратной связи сравнивает исходные параметры отправки даже после разбора командой. Новых уведомлений при повторе или отметке ответа нет.
